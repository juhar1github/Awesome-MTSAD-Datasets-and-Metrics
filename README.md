# Awesome MTSAD Datasets and Metrics

A curated collection of datasets and evaluation metrics for multivariate time-series anomaly detection (MTSAD).

The collection prioritizes original dataset pages, official repositories, primary papers, public implementations, access conditions, and evaluation cautions that materially affect reproducibility.

Last updated: 29 July 2026

## Evaluation metrics

| Metric | Input | What it measures | Paper or definition | Implementation | Best use | Main caution |
|---|---|---|---|---|---|---|
| Point-wise precision, recall, and F1 | Binary predictions and point labels | Per-timestamp classification performance | [Precision and recall definitions](https://scikit-learn.org/stable/modules/model_evaluation.html#precision-recall-f-measure-metrics) | [scikit-learn](https://scikit-learn.org/stable/modules/classes.html#module-sklearn.metrics) | Point anomalies or as a transparent baseline | Ignores event duration and temporal proximity. F1 depends on the selected threshold. |
| AUROC | Continuous anomaly scores and point labels | Ranking across all score thresholds using true-positive and false-positive rates | [ROC AUC documentation](https://scikit-learn.org/stable/modules/model_evaluation.html#roc-metrics) | [scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_auc_score.html) | Threshold-independent ranking when both classes are adequately represented | Can look optimistic under severe class imbalance and gives no special treatment to anomaly intervals. |
| AUPRC or average precision | Continuous anomaly scores and point labels | Precision-recall trade-off across thresholds | [Precision-recall documentation](https://scikit-learn.org/stable/modules/model_evaluation.html#precision-recall-f-measure-metrics) | [scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html) | Strong default for highly imbalanced anomaly labels | Still point-wise and insensitive to early versus delayed detections. State whether trapezoidal AUPRC or average precision is used. |
| Range-based precision, recall, and F1 | Binary predicted ranges and labeled ranges | Existence, overlap, cardinality, and optional positional bias for anomaly intervals | [Precision and Recall for Time Series, NeurIPS 2018](https://proceedings.neurips.cc/paper/2018/hash/8f468c873a32bb0619eaeb2050ba45d1-Abstract.html) | [PRTS](https://github.com/CompML/PRTS) | Subsequence or event anomalies where partial coverage matters | Results depend on existence reward, cardinality, and positional-bias parameters; report every setting. |
| Affiliation precision, recall, and F1 | Predicted and ground-truth event intervals | Local event detection quality using zones around each ground-truth event | [Local Evaluation of Time Series Anomaly Detection Algorithms, KDD 2022](https://doi.org/10.1145/3534678.3539339) | [Official Python code](https://github.com/ahstat/affiliation-metrics-py) | Comparing detections around separate anomaly events | Report alongside a threshold-independent PR-based metric rather than as the only result. |
| Range-AUC-ROC and Range-AUC-PR | Continuous scores and range labels | Threshold-independent ranking with temporal tolerance around labeled ranges | [VUS paper, PVLDB 2022](https://www.vldb.org/pvldb/vol15/p2774-paparrizos.pdf) | [Official VUS code](https://github.com/thedatumorg/VUS) | Subsequence anomalies with slight label or detection misalignment | Requires a maximum buffer or window setting. PR-based results are generally more informative under class imbalance. |
| VUS-ROC and VUS-PR | Continuous scores and range labels | Volume under range-AUC surfaces while varying temporal tolerance | [VUS paper, PVLDB 2022](https://www.vldb.org/pvldb/vol15/p2774-paparrizos.pdf) | [Official VUS code](https://github.com/thedatumorg/VUS) | Robust, threshold-independent TSAD benchmarking across anomaly ranges | More expensive than ordinary AUC. Report the maximum window and prefer VUS-PR as the primary result on imbalanced datasets. |
| eTaPR | Predicted and ground-truth event intervals | Time-series-aware precision and recall with improved handling of detection overlap | [Enhanced Time-Series Aware Precision and Recall](https://doi.org/10.1145/3477314.3507024) | [Official eTaPR code](https://github.com/saurf4ng/eTaPR) | Industrial-control and security events, including HAI | Metric parameters and event construction must be held constant across methods. |
| PATE | Continuous scores or binary predictions and event labels | Proximity-aware performance with separate treatment of early, delayed, partial, and false detections | [PATE, KDD 2024](https://doi.org/10.1145/3637528.3671971) | [Official PATE code](https://github.com/Raminghorbanii/PATE) | Early-warning systems where timing relative to an event matters | Buffer sizes encode application preferences and must be reported. |
| Detection delay or latency | Detection timestamps and event onset times | Time from anomaly onset to the first valid alert | Define the operational protocol explicitly | Application-specific | Online detection, safety, maintenance, and attack response | Specify time units, missed-event handling, allowed early alarms, and whether the mean, median, or distribution is reported. |
| False alarms per time unit | Alerts and monitored duration | Operational alert burden over hours, days, or system runs | Define the operational protocol explicitly | Application-specific | Deployment-oriented evaluation and long normal periods | Point-wise false-positive rate can hide alert bursts; define how adjacent detections are grouped into one alert. |
| Root-cause Hit at K, Recall at K, MRR, or NDCG | Ranked variables or components and root-cause labels | Quality of anomaly localization or root-cause ranking | Use standard ranking definitions and document multi-cause handling | [scikit-learn ranking metrics](https://scikit-learn.org/stable/modules/model_evaluation.html#multilabel-ranking-metrics) | Datasets with variable-level or component-level root-cause annotations | Do not report localization metrics when only timestamp-level anomaly labels are available. State how ties and multiple causes are handled. |
| Point-adjusted F1 | Binary predictions and anomaly ranges | Counts an entire labeled range as detected after one hit | [Towards a Rigorous Evaluation of Time-Series Anomaly Detection](https://doi.org/10.1609/aaai.v36i7.20709) | Available in several TSAD repositories | Historical comparison only | Do not use it as the sole or primary metric. It can substantially overestimate weak detections, and threshold selection on test labels adds further leakage. |

## Minimum reporting protocol

1. Report at least one threshold-independent PR-based metric, such as AUPRC or VUS-PR.
2. Report one transparent thresholded metric, such as raw point-wise F1, without point adjustment.
3. Add an event-aware metric when ground-truth anomalies are intervals.
4. Select thresholds using training data, validation data, or a stated unsupervised rule, not test labels.
5. State dataset version, retained variables, sampling rate, split, normalization, window size, and label processing.
6. State whether results are macro-averaged per entity, micro-averaged over all timestamps, or computed after concatenation.
7. Report results over multiple random seeds when model training is stochastic.
8. For online systems, report detection latency and false alarms per time unit.

## Contributing

Contributions are welcome through pull requests or issues. For a new dataset, include an original or authoritative data link, a primary reference, access or license information, and a reproducibility note. For a metric, include its definition or paper, an implementation when available, expected inputs, and known limitations.

When updating an existing row, explain any change to dataset statistics, preprocessing, or evaluation interpretation.
